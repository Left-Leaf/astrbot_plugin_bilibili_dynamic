# astrbot_plugin_bilibili

B 站动态蹲饼插件。引擎基于 Node 库 [Left-Leaf/bilibili-user-simulation](https://github.com/Left-Leaf/bilibili-user-simulation)，
由插件以子进程方式拉起的 `node/bridge.ts` 驱动；蹲到的动态交给处理模块
（`processor.py`）重新设计成「转发 B 站动态」的样式，分发到所有已订阅的群。

## 目录结构

```
astrbot_plugin_bilibili/
├─ main.py                 # Star 插件：控制台 Web API、群订阅指令、动态分发
├─ bridge.py               # Node 桥接子进程管理（协议解析 / 指令下发 / 生命周期）
├─ card.py                 # 分享图模块：Pillow 自绘动态卡片
├─ processor.py            # 处理模块：动态 → 分享图 / 图文 / 文本 / 合并转发
├─ pages/console/          # 插件控制台页面（唯一能开启蹲饼、模拟人格的地方）
├─ node/
│  ├─ bridge.ts            # 内核桥接脚本（SimulationKernel + 二维码截图 + 指令通道）
│  └─ package.json         # 依赖：bilibili-user-simulation / puppeteer-extra / tsx
├─ _conf_schema.json       # 插件配置
└─ metadata.yaml
```

## 控制台指令（只有 WebUI 里能开）

蹲饼、模拟人格这类会操纵本机浏览器的能力**不注册为聊天指令**，因此群成员、
私聊用户都无法开启；它们只在插件的 WebUI 页面里可用。入口：WebUI 侧边栏 `插件` →
`B站动态蹲饼` 卡片 → 点卡片上的 🖬 显示器图标（打开 WebUI 页面）。

| 指令 | 说明 |
| --- | --- |
| `deps install` | 安装 Node 依赖（相当于在 `node/` 目录执行 `npm install`，后台运行，进度见安装面板） |
| `start` | 启动引擎：拉起 Node 内核并打开浏览器（不开启任何功能） |
| `stop` | 关闭引擎：结束浏览器与 Node 进程 |
| `login` | 确保登录，未登录时生成二维码（页面自动显示，可直接扫码） |
| `fetch on` / `fetch off` | 开启 / 关闭蹲饼（开启时只投递增量基线之后的动态，关闭会同时关掉动态页标签） |
| `sim on` / `sim off` | 开启 / 结束模拟人格（养号任务流） |
| `status` | 内核状态快照 |
| `dynamics [n]` | 查看最近捕获的动态 |
| `help` | 内核内置指令列表 |

控制台页面还会展示群订阅表、最近捕获的动态、分发记录、Node 依赖状态与引擎日志。
页面上的按钮等价于下发上述指令。

## 群订阅：群 → 关注 UP 列表（用户侧，仅管理员）

**蹲饼不筛选**：依赖库按增量基线把关注流里**全部 UP** 的新动态原样回传，筛选完全由插件完成。
订阅的单位不是「整个群开/关」，而是**该群关注了哪些 UP**：

| 指令 | 说明 |
| --- | --- |
| `/关注up <uid 或空间链接>` | 把该 UP 加入**本群**关注列表，同时在浏览器里关注它（AstrBot 管理员，群聊内发送） |
| `/取关up <uid 或空间链接>` | 把它移出本群关注列表（**不会**在 B 站上取关，其他群不受影响） |
| `/关注列表` | 查看本群关注的 UP |

分发规则：捕获到一条动态后，插件按动态作者的 uid 查找「关注了该 UP」的群，只发给这些群；
同一个 UP 可以被多个群分别订阅，互不影响；没被任何群关注的 UP，其动态不会被分发。

订阅表以 `unified_msg_origin`（平台 + 会话）为键存在
`data/plugin_data/astrbot_plugin_bilibili/subscribers.json`，结构形如：

```json
{
  "default:GroupMessage:927820185": {
    "umo": "default:GroupMessage:927820185",
    "platform_name": "aiocqhttp",
    "group_id": "927820185",
    "targets": [{ "uid": "161775300", "name": "明日方舟" }]
  }
}
```

细节：

* **名称自动获取**：订阅时库的 `followUp()` 会从 UP 主页读回 uid 与昵称；万一没读到，
  插件会在第一次捕获到该作者动态时用动态里的作者名自动回填；
* **关注是幂等的**：已关注的 UP 不会重复点击，全程在临时标签页完成，不中断正在跑的模拟任务；
* 需要在控制台 `start` 启动引擎：引擎未启动时仍会记录订阅，但不会真正关注该 UP
  （回复里会提示启动后重发一次）；
* 这里的「管理员」指 AstrBot 管理员（`配置 → 其他配置 → 管理员 ID`），可先让管理员在群里
  发送 `/sid` 拿到 `UID` 再填入；非管理员发送这些指令会被权限过滤器拦下。

## 管理员指令（关注 / 取关 UP）

上面三个指令由插件接到聊天侧，底层用的是依赖库的**运行态关注**能力
（`kernel.followUp(uid)` / 内核指令 `follow <uid>`，独立于模拟任务流、幂等、不打扰正在跑的任务），
也可以在控制台直接下发：

```
follow 161775300
```

## 分发样式（`message_style`）

默认 **自绘分享图**：插件用 Pillow 把动态画成一张图（不访问 B 站页面、不依赖
第三方文转图服务），配色与排版是本插件自己的风格。

* 头部：UP 头像 + 昵称 + 发布时间；
* 正文：完整文本（自动折行，支持 emoji）；
* 内容：图文动态画**全部图片**（1/2/3 列网格，等比裁切）；视频/直播/番剧/课程/专栏
  只画**封面 + 标题 + 链接**；
* **内嵌转发的动态**：画成带左侧色条的**引用块**，块内按同样标准继续画
  （作者 / 正文 / 图片 / 链接），最多 3 层；
* 底部：动态详情链接。

样式可选值：

* `auto`（默认）：发上面那张分享图（渲染失败自动退回 `rich`）；
* `rich`：一条消息里依次发「文字块 + 该块的全部图片」，内嵌转发同样按此标准排在后面；
* `text`：只发文字（含内嵌体的文字与链接，不带图），全平台可用；
* `forward`：QQ 合并转发消息，节点昵称 = UP 主，内容同 `text`。

> 为什么不用 QQ 的 `com.tencent.structmsg` 分享卡片：在 NapCat / QQNT 上收端会把它
> 渲染成「发送者版本过低，无法展示内容」，而发送侧无法感知这个回退，因此已移除卡片模式。

分享图保存在插件数据目录的 `cards/<动态id>.png`，控制台也可以随时重画：

```
card 1245555131632582824
```

### 新动态怎么判定

内核支持**增量基线**：`fetch on` 时插件会把「上次已见动态的最新时间」（存在插件数据目录的
`watermark.json`）作为 `baselineTs` 交给内核，内核只投递这个时间**之后**的动态（首屏不够会
自动滚动补全，不缺失）；关掉蹲饼时内核还会返回本次的最终基线，插件据此推进水位。

插件侧再做一层兜底过滤：只有**发布时间晚于水位**的动态才会分发，不晚于水位的直接跳过
（日志/分发记录会写明跳过了几条）。水位的粒度是「秒」，同一秒发布的多条会一起被当成新一轮。

* 晚于水位 → 新动态 → 按群订阅筛选后分发，并把水位抬到这批里最新的时间；
* 不晚于水位 → 旧动态 → 跳过；
* 还没有水位（刚装好插件/删过 `watermark.json`）→ 内核从「当前时间」开始投递，
  送来的本来就是新动态，直接分发（不会把历史动态刷屏）。

**登录态**保存在插件数据目录的 `browser_profile/`（不是依赖包目录），所以 `npm install`
更新依赖不会丢掉 B 站登录；若要手动指定，改配置项 `user_data_dir`。

## 安装与首次运行

1. 在 WebUI 侧边栏 `插件` 里点 `B站动态蹲饼` 卡片上的 🖬 图标打开控制台。
   **没有安装依赖时，页面只会显示一个安装面板**：点「安装 Node 依赖」按钮，插件就会在后台对 `node/`
   目录执行 `npm install`（安装 bilibili-user-simulation / puppeteer-extra / tsx，并下载 Chromium，
   首次耗时数分钟），进度与 npm 输出实时显示在同一个面板里；装完页面会自动进入控制台。

   也可以自己手动装：`cd data/plugins/astrbot_plugin_bilibili/node && npm install`。

2. 点 ⚙️ 图标编辑插件配置（分发样式、渲染参数、依赖路径等；蹲饼目标在群里用 `/关注up` 配置）。
3. 依次执行：`start` → `login`（页面出现二维码后用 B 站 App 扫码）→ `fetch on`。
4. 在需要的群里由管理员发送 `/关注up <uid>`（例如 `/关注up 161775300`），
   之后该 UP 的新动态会自动分发到这个群。

引擎在插件卸载 / 重载时会自动关闭；如需手动关闭请在控制台执行 `stop`。
